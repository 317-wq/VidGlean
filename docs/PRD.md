## 1. 产品概述

### 1.1 产品定位

VidGlean 是一款本地 AI 视频内容总结工具。

用户通过粘贴视频链接，将视频内容交给 AI 分析，最终生成结构化的 Markdown 知识文档。第一版只支持视频链接导入，本地视频上传作为后续能力保留。

产品主要解决的问题：

用户不想花费大量时间观看视频，但希望快速了解视频内容、提取重要知识点，并将有价值的信息沉淀为可阅读、可检索的 Markdown 文档。

### 1.2 核心理念

- 第一版只支持视频链接导入；本地视频上传作为后续能力保留。
- Markdown 文档是产品的核心产物。
- 以文档为中心，而不是以视频管理为中心。
- AI 负责理解视频内容、生成总结和辅助修改。
- 用户拥有模板选择权和文档修改确认权。
- 本地运行，用户自行配置 AI API。

### 1.3 产品形态

- Windows 桌面应用。
- 无需注册账号或登录。
- 无需开发者提供云端服务器。
- 用户自行配置 AI 服务 API Key。
- 视频信息、字幕、任务记录、Markdown 文档等保存在本地。

需要说明：调用第三方模型服务时，相关字幕或文本内容会发送给用户配置的模型服务商，不能将其描述为完全不联网的数据处理。

## 2. 视频导入模块

### 2.1 视频链接导入（核心功能）

支持用户粘贴一个或多个视频链接。

第一版仅支持：

- Bilibili：视频页链接、b23.tv 短链、BV 号。

抖音及其他平台不纳入第一版，后续按平台适配的方式逐个扩展。

#### 导入流程

1. 用户粘贴视频链接。
2. 软件自动识别平台并解析链接。
3. 获取视频基本信息。
4. 检查链接有效性、平台支持情况和重复记录。
5. 展示解析预览。
6. 用户可以移除不需要的视频。
7. 用户点击确认导入。
8. 视频进入处理任务队列。

#### 视频信息

尽可能获取：

- 视频标题
- 视频封面
- 视频作者
- 来源平台
- 视频时长
- 视频原始链接

解析预览必须显示封面，方便用户辨认视频。

#### 异常情况

- 无效链接：明确提示原因。
- 不支持的平台：明确提示暂不支持。
- 需要登录：提示当前视频可能需要登录后才能访问。
- 视频不存在：提示视频可能已删除或设置为私密。
- 网络异常：提示检查网络。
- 解析失败：允许修改链接和单独重新解析。

#### 重复视频

- 以平台视频 ID 判重（当前为 BV 号），同一个视频的不同写法（短链、带追踪参数的链接）视为同一条视频。
- 默认不重复创建记录。
- 提示用户已有对应文档。
- 用户可以查看已有文档，或者选择重新生成总结。

#### 字幕获取

优先获取平台提供的字幕。

第一版只处理有字幕的视频。获取不到字幕时，任务在字幕阶段失败，明确提示「该视频没有可用字幕，暂不支持」，用户可以选择删除该任务。无字幕视频的音频提取与 ASR 识别属于后续增强。

获取 Bilibili 字幕需要用户配置登录凭证（SESSDATA）。未配置凭证或凭证失效时，单独提示用户完成配置或更新凭证，不要把鉴权失败笼统归因为「视频没有字幕」。

默认不下载完整视频，只保存必要的视频元信息、字幕和总结内容。

### 2.2 本地视频上传（暂不纳入第一版）

本节保留作为后续设计参考。第一版不提供本地上传入口，正式实现前需要重新评审。

后续实现时支持：

- 点击选择视频文件。
- 拖拽视频文件。
- 一次选择多个视频。

支持的格式：

- MP4
- MOV
- WebM

上传前检查文件格式和大小。

默认文件大小上限暂定为 2GB，用户可以在设置中调整。

#### 上传规则

- 上传前展示待上传列表。
- 显示文件名、文件大小和格式。
- 用户可以移除待上传文件。
- 用户确认后正式上传。
- 上传完成后进入视频处理流程。

软件复制视频到自己的数据目录，不修改用户原始文件。

即使用户移动或删除原始文件，软件中的副本仍然保留。

#### 进度展示

- 总体上传进度。
- 每个文件独立上传进度。
- 上传完成与后续处理阶段分别展示。

## 4. 任务管理模块

### 4.1 任务状态

- 等待中
- 处理中
- 已完成
- 失败
- 已取消

### 4.2 任务处理阶段

第一版任务阶段：

1. 链接解析
2. 字幕获取
3. AI 内容分析
4. Markdown 总结生成

本地上传相关的阶段（文件导入、音频提取、字幕识别）不在第一版范围内。

每个阶段独立记录执行状态。

### 4.3 任务重试

失败后允许重新执行。

从失败阶段继续，不重复执行已经成功的阶段。

例如：

链接解析成功、字幕获取成功、AI 总结失败。

重新执行时直接从 AI 总结阶段开始。

### 4.4 暂停、继续和取消

支持：

- 暂停任务。
- 继续任务。
- 取消任务。

取消任务不等于删除文档或已导入内容。

### 4.5 并发控制

采用限制并发模式。

默认配置：

- 视频任务并发数：2。
- AI 请求并发数：2。

用户可以分别调整。

超过并发限制的任务进入等待队列。

第一版不做复杂的动态调度。

遇到 API 限流时采用自动退避重试。

### 4.6 关闭软件时的任务处理

正常关闭软件时：

- 没有正在执行的任务：直接退出。
- 存在正在执行的任务：提示用户选择。

用户可以选择：

1. 继续等待任务完成。
2. 保存进度并退出。

保存进度后，下次启动恢复未完成任务。

已经成功的阶段不重复执行。

### 4.7 意外崩溃

软件意外崩溃后：

- 保留已经成功保存的任务阶段结果。
- 保留已经获取的字幕和文档。
- 重新启动后不自动恢复未完成任务。
- 提示用户存在未完成任务。
- 用户自行决定是否手动重试。

## 5. AI 总结生成模块

### 5.1 自动总结

用户不需要编写复杂提示词，默认情况下 AI 自动分析视频内容并生成总结。

允许用户在生成前填写额外要求。

例如：

“重点整理 C++ 并发编程知识，提取关键概念、代码示例和面试考点。”

### 5.2 总结深度

提供三个档位：

**简洁**

适用于娱乐内容、短视频和快速了解。

**标准**

适用于普通知识分享、经验总结。

**详细**

适用于技术教程、课程和深度科普。

默认由 AI 根据视频类型和知识密度决定。

用户手动选择时，以用户选择为准。

### 5.3 视频类型识别

采用一个主要类型和多个辅助标签。

初步类型：

- 技术教程
- 知识科普
- 经验分享
- 观点讨论
- 生活技巧
- 娱乐内容

AI 自动识别，用户可以修改。

### 5.4 不同内容类型的总结策略

技术教程：重点提取原理、步骤、代码和实际问题。

知识科普：解释概念、背景和结论。

经验分享：整理经验、方法和建议。

观点讨论：提取观点、论据和结论。

生活技巧：突出可执行步骤。

娱乐内容：以简短概述为主。

AI 根据实际内容动态调整文档章节，不强制填充所有章节。

### 5.5 时间戳（暂不纳入第一版）

第一版不生成时间戳，也不提供时间戳跳转。

原因：时间戳要求字幕保留分段与时间信息，并要求模型稳定输出结构化引用，会同时增加提示词、输出解析和渲染三处的复杂度。第一版优先保证正文质量与文档可用性。

后续版本再评估该能力，前提是：字幕分段数据可用、模型能稳定输出引用位置、平台支持时间定位。不能准确定位的内容不强行生成时间戳。

### 5.6 代码、公式和命令行

自动识别有价值的内容：

- 代码使用对应语言的 Markdown 代码块。
- 数学公式使用 LaTeX。
- 命令行使用 Shell 代码块。

没有相关内容时不强行生成。

### 5.7 Markdown 模板

采用：

通用模板 + 类型专属模板 + AI 动态生成。

通用模板提供基础结构，例如：

- 一句话概述
- 内容大纲
- 核心内容
- 关键结论

类型专属模板提供特定内容结构。

AI 可以根据实际内容增加、删除和调整章节。

### 5.8 重新生成总结

已完成的文档允许重新生成。

用户可以：

- 修改总结深度。
- 修改额外要求。
- 重新识别视频类型。
- 更换 Markdown 模板。

重新生成时复用已有字幕。

如果生成失败，保留旧总结。

如果生成成功并产生新旧两个版本，由用户选择保留哪一个，最终只保留一个正式版本。

### 5.9 AI 辅助修改

支持用户通过自然语言要求 AI 修改：

- 指定章节。
- 整篇文档。
- 补充某些知识点。
- 修正内容。
- 调整表达方式。

采用预览确认机制：

1. 用户提出修改要求。
2. AI 生成修改结果。
3. 展示修改前后的差异。
4. 用户确认后应用。
5. 用户可以放弃修改。

未经确认不覆盖正式文档。

## 9. AI 对话模块

### 9.1 对话定位

每篇 Markdown 文档拥有独立的 AI 对话。

不是全局视频助手，也不支持跨视频问答。

### 9.2 AI 上下文

AI 回答时使用：

- 当前文档的 Markdown 总结。
- 当前文档对应的原始字幕。
- 当前文档独立的历史对话。

优先结合 Markdown 理解，必要时参考原始字幕。

### 9.3 对话能力

支持：

- 解释知识点。
- 补充示例。
- 纠正错误。
- 扩展内容。
- 针对文档内容进行提问。
- 根据要求修改或补充文档。

### 9.4 对话历史

每篇文档拥有独立对话历史。

重新打开文档后可以继续之前的对话。

不同文档之间的上下文相互隔离。

支持清空整段对话历史。

不支持单条消息删除。

### 9.5 文档更新

重新生成 Markdown 后：

- 保留原有对话历史。
- AI 后续回答优先使用最新文档和字幕。
- 如果历史结论与新文档冲突，以最新内容为准。
- 必要时说明文档已经更新。

## 10. Markdown 模板管理

### 10.1 内置模板

软件提供不同类型的内置 Markdown 模板。

### 10.2 自定义模板

用户可以上传自己的 Markdown 模板。

支持在软件内查看模板全文，并直接编辑自定义模板；保存后立即生效，已生成的文档不受影响。

内置模板只读：可以查看，也可以「另存为副本」后编辑，避免误改内置结构。

上传时可以从本地选择 `.md` 文件，也可以直接粘贴内容。

### 10.3 模板校验

上传时自动校验：

- 文件格式是否为 `.md`。
- 模板变量是否符合规范。
- 是否存在未知占位符。
- 必要变量是否缺失。

校验失败时展示具体错误原因。

### 10.4 模板名称

内置模板和自定义模板统一检查名称。

不允许重名。

### 10.5 模板删除

删除模板不影响已经生成的 Markdown 文档。

### 10.6 默认模板

支持设置默认模板。

AI 仍然根据视频内容推荐模板。

默认模板只是优先选择，不强制使用。

每次生成前，用户必须确认最终使用的模板。

没有设置默认模板时，AI 根据当前视频独立推荐，不记住上一次的模板选择。

### 10.7 模板推荐

AI 识别视频类型后推荐模板。

如果视频内容跨多个类型，可以推荐多个模板并说明原因。

用户可以手动选择其他模板。

生成前展示：

- 模板名称
- 模板简介
- 适用场景
- AI 推荐理由

不强制提供模板结构预览。

## 11. AI 服务配置模块

### 11.1 API 兼容性

第一版只支持 OpenAI 兼容 API。

配置项：

- API Base URL
- API Key
- Model Name

兼容 DeepSeek、OpenAI 及其他兼容服务商。

### 11.2 模型管理

支持：

- 添加多个模型配置。
- 编辑模型配置。
- 删除模型配置。
- 测试 API 连接。
- 切换当前模型。

第一版所有 AI 任务默认使用当前选定模型。

暂不支持不同任务指定不同模型。

### 11.3 高级参数

提供：

- Temperature
- Max Tokens
- 请求超时时间

普通用户不需要修改这些参数。

### 11.4 异常处理

明确提示：

- API Key 无效。
- 余额不足。
- 模型不存在。
- 请求超时。
- API 限流。
- 网络连接异常。

AI 任务失败时保留已经获取的视频信息、字幕和其他成功阶段结果。

支持重新执行失败阶段。

- AI 对话 Token 消耗。

## 13. 数据存储与备份

### 13.1 本地数据存储

所有核心数据保存在本地。

#### 内容真源约定

Markdown 正文以磁盘上的 .md 文件为内容真源。SQLite 只保存元数据、分类标签、任务记录、对话历史、Token 用量和搜索索引，不重复保存正文。

- 文档记录与文件通过稳定的文档 ID 对应，文件名可以随标题变化，ID 不变。
- 正文的任何修改先写入文件，成功后再更新索引。
- 用户在外部编辑器中修改 .md 文件后，软件在下次启动或重新扫描时检测到变化并重建索引，不覆盖用户的改动。
- 删除文档时按第 14 章处理文件，同时清理数据库中的关联记录。

包括：

- Markdown 文档
- 原始字幕
- 视频元信息
- 分类
- 标签
- 星标
- 个人备注
- 任务记录
- AI 对话历史

### 13.2 自定义数据目录

默认使用软件数据目录。

用户可以修改存储位置。

支持迁移已有数据。

迁移过程中保留原数据，迁移成功后再处理旧数据，避免失败导致数据丢失。

### 13.3 备份与恢复

支持用户手动备份和恢复。

备份内容包括：

- Markdown 文档
- 原始字幕
- 视频元信息
- 分类
- 标签
- 星标
- 个人备注
- 任务记录

API Key 等敏感配置单独保护，不直接作为普通明文备份内容。

第一版不支持云端同步和自动备份。

### 13.4 加密备份

支持可选加密备份。

普通备份直接导出。

加密备份由用户设置密码。

恢复时需要输入对应密码。

忘记密码无法恢复，需要明确提醒。

### 13.5 自动保存

支持：

- Markdown 编辑内容自动保存。
- 个人备注自动保存。
- 分类自动保存。
- 标签自动保存。

显示保存状态：

- 保存中
- 已保存

异常关闭时尽可能恢复最近一次成功保存的内容。

## 14. 文档删除与回收站

删除文档前必须二次确认。

统一删除文档及关联数据：

- Markdown 文档
- 原始字幕
- AI 对话历史
- 个人备注
- 其他关联数据

不影响其他文档和分类。

如果文档关联多个分类，只解除关联，不删除分类本身。

优先尝试将对应 Markdown 文件放入 Windows 系统回收站。

如果无法可靠地实现关联数据处理，则采用直接删除，并明确提示用户。

不开发软件内部回收站。

## 16. 异常处理与错误日志

### 16.1 错误提示

能够准确判断错误原因时，直接展示具体原因。

无法准确判断时显示「未知错误」。

提供查看详细错误日志入口。

### 16.2 日志信息

详细日志包括：

- 错误时间
- 任务 ID
- 处理阶段
- 错误代码
- 异常详情

必须过滤 API Key、密码等敏感信息。

### 16.3 日志导出

支持导出 `.log` 或 `.txt` 文件。

支持：

- 导出全部日志。
- 导出指定时间范围的日志。

导出时再次过滤敏感信息。

### 16.4 日志自动清理

默认保留最近 30 天的日志。

用户可以调整保留期限。

超过期限的日志自动清理。

用户手动导出的日志文件不受自动清理影响。

### 16.5 自动重试

针对临时性错误自动重试：

- 网络超时
- 连接中断
- API 限流
- 服务器暂时不可用

使用逐步延长等待时间的退避策略。

对于无效链接、平台不支持、API Key 错误等非临时性错误，不进行无意义的自动重试。

### 16.6 重试次数

用户可以调整最大自动重试次数。

提供默认值和最大限制，避免无限重试。

### 16.7 重试状态展示

任务页面展示：

- 失败原因。
- 当前重试次数。
- 最大重试次数。
- 下次重试时间。
- 当前处理阶段。

例如：

「字幕获取失败：网络连接超时」

「正在进行第 2 / 3 次重试，5 秒后重新执行。」

### 16.8 取消自动重试

用户可以手动取消本次自动重试。

取消后任务停止自动重试，之前已经完成的阶段结果保留。

用户可以之后手动重新执行。

## 17. 数据安全与隐私

### 17.1 软件访问控制

不设置软件启动密码。

打开软件直接进入首页。

不需要账号注册和登录。

### 17.2 敏感凭证安全

敏感凭证包括 AI 服务的 API Key 和平台登录凭证（Bilibili 的 SESSDATA）。

使用 Windows 系统凭据管理机制保护上述凭证。

凭证不以明文保存在 SQLite 或普通配置文件中，也不写入应用日志和导出的错误日志。

用户修改或删除模型配置时，同步更新对应凭据；凭证失效时提示用户重新配置。

### 17.3 临时文件清理

设置页面提供「清理临时文件」功能。

清理内容：

- 音频提取临时文件。
- 无用缓存。
- 失败任务遗留的临时数据。

清理前展示预计释放空间并进行确认。

不得误删正式 Markdown 文档、原始字幕和用户配置。

### 17.4 卸载数据处理

卸载时提供两种选择：

**保留数据**

卸载软件，但保留 Markdown 文档、字幕、分类、标签、任务记录等用户数据。

**删除数据**

卸载软件，同时删除 VidGlean 管理的本地数据。

删除前二次确认，并明确提示不可恢复。

## 21. 技术事项

### 已确定的前提

以下内容已经确定，后续技术设计不得与之冲突：

1. 第一版只支持 Bilibili，不做抖音，不做本地视频上传。
2. 第一版不生成时间戳，不做时间定位跳转。
3. Markdown 文件是内容真源，数据库只做元数据与索引。
4. 单机本地运行，不引入云端服务；AI 能力由用户自备 OpenAI 兼容 API。

### 技术方案

技术栈与架构已确定，详见 [ARCHITECTURE.md](ARCHITECTURE.md)。要点：

- Python 3.12 + FastAPI 后端，pywebview 作为桌面壳，单进程运行。
- 前端为原生 HTML / CSS / ES Module，无构建链。
- SQLite 存储元数据与索引，Markdown 文件为正文真源。
- 不引入 ORM、任务队列、WebSocket、云服务。

### 仍需验证的事项

以下内容在实现过程中验证，不作为「已确定」对待：

1. pywebview 在 Windows 10 上的 WebView2 运行时依赖与打包方式。
2. Bilibili 接口与字幕获取的稳定性（接口变更、凭证失效、限流）。
3. FTS5 + 中文分词的实际搜索效果。
4. Windows 安装包与更新回滚的可实现性。

## 22. 产品核心原则

VidGlean 的开发应始终遵循以下原则：

1. **文档优先**：最终交付物是 Markdown 文档，而不是视频。
2. **链接优先**：视频链接导入是主要使用场景。
3. **本地优先**：用户的数据由本地软件管理。
4. **AI 辅助**：AI 负责分析和生成，但重要修改由用户确认。
5. **简单易用**：不为了功能数量而增加不必要的复杂度。
6. **数据安全**：避免误删、覆盖和敏感信息泄露。
7. **渐进开发**：先完成核心链路，再逐步增加增强功能。

**产品最终目标：用户只需要提供一个视频链接，就能获得一份结构清晰、内容有价值、可以长期保存和检索的 Markdown 知识文档。**
